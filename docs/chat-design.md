# Product chat

Request: add AI chat using assistant-ui and Blume, review their documentation/subpages, use DeepSeek through the user's OpenRouter credential and OpenAI-compatible calls, and Claude Agent SDK through LiteLLM translation.

The product/version selector owns chat scope. Blume's reusable `useAssistant` hook sends bounded conversation history and receives a plain UTF-8 answer stream. assistant-ui's external store runtime supplies the transcript, composer and message actions. A separate run metadata endpoint supplies verified sources and model-composed generative UI. The metadata is bound to the conversation, product and exact revision/release; switching context starts a new conversation. Stop/clear aborts and clears the Blume conversation.

FastAPI retrieves prepared evidence before starting generation and preserves the existing draft/published snapshot rules. Claude Agent SDK runs in a temporary directory with custom knowledge/presentation tools only, no filesystem or shell tools, no user/project settings, and bounded turns. Source text and earlier conversation are data, never instructions. Read-only tools return product evidence and readiness. Citations resolve only to retrieved evidence; presentation components are allowlisted and validated, without model-provided executable content or source URLs.

The local authenticated Messages endpoint uses LiteLLM's Anthropic adapter, forwarding through OpenRouter's OpenAI-compatible Chat Completions interface to DeepSeek. The upstream key and local gateway token stay in the ignored server `.env`. The configured gateway URL also supports container loopback. Public status returns model/configuration availability only. Provider failures are sanitized; an unavailable model produces an actionable error, without pretending a canned answer was generated.

The interface keeps the approved light/red Inter/Geist block design: a quiet transcript, focused composer, starter questions, source evidence and useful generative tables/facts. Chat history is session-local in this version; the browser's source/run metadata lasts only for the server's bounded retention window. It does not publish or edit products.

Implementation sequence: verify official docs and package APIs; add server gateway/agent and scoped streaming/metadata contracts with regression tests; integrate Blume/assistant-ui and validated generative renderers; exercise real DeepSeek with synthetic evidence; run backend/browser/build and review. No additional account setup is needed for the supplied OpenRouter credential.

The final run contract uses a unique request UUID for every turn, separate from the conversation UUID. Completed packets remain keyed by request UUID; a refused turn has no packet to reuse. The client waits for its matching packet before permitting the next send and validates request/product-version identity. The server reserves conversations under a lock before retrieval, permits three active requests, expires abandoned reservations, and evicts/ages retained metadata. SDK transport, translated SSE iterator and actual provider stream are all owned and closed explicitly. Model Markdown cannot load images or execute HTML; errors are sanitized before they enter adapter events/logs. The pinned LiteLLM adapter methods are used explicitly so the underlying OpenAI stream remains available for deterministic closure.

The provider boundary follows the OpenAI Chat Completions contract (`model`, role/content `messages`, function tools, and streamed completion deltas), checked against the installed SDK and the [official OpenAI API reference](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create). LiteLLM translates these responses back to the Anthropic Messages contract consumed by Claude Agent SDK.
